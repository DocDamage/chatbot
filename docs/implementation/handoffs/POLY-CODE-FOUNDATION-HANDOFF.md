# Polyglot coding foundation handoff

- Objective: implement the repository-aware polyglot coding upgrade plan.
- Scope completed in this change: capability registry, repository snapshot/intelligence, TypeScript AST provider with labeled fallback, relationship queries, structural retrieval, adaptive context allocation, typed controller/request artifacts, natural-language preconditioned editing, safe command capability runner, diagnostics, bounded repair controller, staged review, test strategy, shared coding authorization, knowledge provenance, coding model metadata plus provider-routed structured patch drafting, explicit write-gated patch application, client workflow controls, multi-family fixture manifest, and benchmark scoring/toolchain preflight.
- Runtime integration: `CodingAgent`, `EnhancedOrchestrator`, and `src/server/routes/code.ts`.
- Production boundary: coding remains local-only experimental; this handoff does not promote the feature in the production manifest.
- Verification: server and test type-checks, client type-check, server lint, server build, focused coding/orchestrator/provider/client tests, and `npm run eval:coding` plus upgraded preflight.
- Known limitations: benchmark reports now score visible checks, repository selection, API accuracy, root-cause evidence, review quality, and verification honesty, but the runner still does not invoke a live coding model, apply generated patches, or execute hidden checks. Some optional toolchains remain unsupported and provider-specific AST adapters are still labeled fallback. The repository-wide release coverage baseline remains open: the existing threshold is anchored to an older baseline and the current checkout already exceeds it before this upgrade; it was not weakened.
- Rollback: remove/disable the new coding endpoints/controller integration and retain the existing `CodingAgent`, `CodeReviewer`, `PatchGenerator`, and `VerificationRunner` compatibility paths.
