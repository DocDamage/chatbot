The complete root tree improved from 52 findings (3 critical, 15 high, 30 moderate, 4 low) to five low-severity nodes after the shipped-runtime work and a planned Jest 30 / ESLint 10 development-tool migration. Those five nodes are one advisory propagated through `deepmerge -> jest-config -> @jest/core/jest-cli -> jest`; there are no other root findings. The actual deepmerge code is locally patched and exploit-tested, while the scanner correctly continues to report the published 4.3.1 version. Client, desktop companion, coding-tools, and REA complete-tree audits are clean. No `npm audit fix --force` downgrade was accepted.

## Affected runtime paths and fixes

- Express request handling used vulnerable `proxy-addr`, `body-parser`, and `qs` versions. Compatible overrides move them to 2.0.8, 1.20.9, and 6.17.1. This closes the critical IP-spoofing path used by proxy trust decisions and the request-body/query denial-of-service paths ([proxy-addr advisory](https://github.com/advisories/GHSA-jqcg-44mw-7w3h)).
- HTTP clients across health checks, providers, web search, knowledge ingestion, webhooks, and voice used vulnerable Axios/follow-redirects releases. Axios is now 1.21.0 and follow-redirects is 1.16.2.
- EPUB/archive ingestion and the ONNX path used `adm-zip` 0.6.0. The direct and transitive graph now resolves to 0.6.1, addressing decompression, duplicate-entry, permission-bit, and process-crash advisories.
- DOCX ingestion through Mammoth used `@xmldom/xmldom` 0.8.13. A same-line override moves it to 0.8.15, closing XML injection and malformed-input resource-exhaustion paths.
- Request, configuration, workflow, chat, governance, and DABOOK validation used Zod 3. The package is now patched Zod 4.6.7 ([oversized-collection advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)); existing schemas import the package's `zod/v3` compatibility export to retain established parsing and inferred types without a risky repository-wide schema rewrite.
- Local embeddings/image generation, OCR/sprite processing, browser jobs, CSV ingestion, and context serialization now use `@huggingface/transformers` 4.3.2, Sharp 0.35.5, Puppeteer 25.16.0, csv-parse 7.0.3, and TOON 2.3.1 respectively.
- Cheerio's network stack is constrained to patched Undici 7.30.1. The client lock updates Zod, Vite/Vitest, Undici, source-map, and related dependencies. Assistant UI remains pinned to the verified React 0.14.5/core 0.2.2/store 0.2.10/tap 0.5.11 combination: updating that combination introduced a render loop during browser validation. The restored combination passes the full client suite, accessibility, browser workflows, and a clean dependency audit. `radix-ui` 1.8.1 is now an explicit production dependency because Assistant UI imports it at runtime; this prevents production materialization from relying solely on a transitive hoist.
- Electron is updated within major 43 to 43.8.6, with patched Undici. The desktop package is audited as a complete tree because Electron is a development dependency in the manifest but is the delivered runtime.
- Coding tools retain Context7 4.4.4 while constraining its Hono server to 2.1.5 and minimatch to 11.0.3. REA 6.8.0 similarly receives scoped Zod 4.6.7, glob 14.0.3, and minimatch 11.0.3 overrides while upstream exact pins lag.
- Root development-only Handlebars, shell-quote, js-yaml, and brace-expansion critical/high findings were removed with compatible same-major overrides.

## Development-tool migration

The remaining 31 root findings were traced to Jest 29, ESLint 8, and their glob/minimatch chains. The compatible migration now uses [Jest 30.5.2](https://jestjs.io/docs/upgrading-to-jest30), ts-jest 29.4.15 (which declares Jest 30 support), `@types/jest` 30.0.0, [ESLint 10.14.0](https://eslint.org/docs/latest/use/migrate-to-10.0.0), `@eslint/js` 10.0.1, and TypeScript-ESLint 8.72.1. The resolved tool graph uses glob 14.0.3 and minimatch 11.0.3, both beyond the affected advisory versions.

Jest 30 removed the singular `--testPathPattern` CLI option. Six package scripts, three verification-command descriptors, the canonical-command Jest spawn, and one command-line fixture now use `--testPathPatterns`. No removed Jest matcher aliases, `genMockFromModule`, or Jest-internal imports were present. Nine test files used the Jest 29-era `jest.fn<any>()` generic form; those mocks now declare an explicit callable type, preserving their implementations and assertions while satisfying Jest 30's stricter mock inference.

The repository already used ESLint flat configuration. ESLint 10's newly recommended `preserve-caught-error` and `no-useless-assignment` rules, plus unused-disable reporting, were held at the established ESLint 8 baseline so the security migration did not silently redefine the project's lint policy. Existing TypeScript-ESLint rules and client warning policy remain enabled.

Fresh npm 11 lock materialization initially exposed stale optional peer ranges across six direct Tree-sitter grammars. Scoped overrides bind only `tree-sitter-c`, `tree-sitter-cpp`, `tree-sitter-java`, `tree-sitter-kotlin`, `tree-sitter-rust`, and `tree-sitter-swift` to the declared root Tree-sitter 0.25.1 dependency. The already-compatible Bash, Go, JavaScript, and Python grammars are untouched. Every overridden grammar was native-parsed with a representative valid source; the provider returned exact native language tags at 0.95 confidence (Kotlin class extraction, and representative class/function extraction for the other five). A persistent six-language regression matrix protects those compatibility assertions.

The [deepmerge advisory](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) has no patched npm release. An initial experiment constrained Jest's development-only `jest-config` chain to 4.1.1 because it is outside the advisory's declared affected range (`>=4.2.0, <=4.3.1`), but an independent exploit probe reproduced the same returned-object prototype poisoning. That downgrade was rejected as security theater.

The graph retains 4.3.1 and applies the minimal `__proto__` guard from [upstream pull request #274](https://github.com/TehShrike/deepmerge/pull/274) through `patch-package --error-on-fail`. The patch covers both source `index.js` and the delivered `dist/cjs.js` main entry. `patches/README.md` records the pristine SHA-256 values, MIT provenance, and upstream attribution. The postinstall wrapper skips only when both Jest and deepmerge are absent (a production-only install), and otherwise fails closed if the target or patch tool is missing. The package allowlist explicitly includes `patches/**` and `scripts/dependencies/**` so source-package installs retain the mechanism. The release dependency gate conditionally executes the same read-only PoC/compatibility test whenever the development target is installed, so `--ignore-scripts` cannot leave an unpatched graph with a passing gate. This is not published or labeled as a custom fixed package version, so `npm audit` truthfully retains the advisory.

Lockfiles were regenerated for root, client, desktop companion, `services/coding-tools`, and `services/rea`. No `npm audit fix --force` or semver-breaking automated audit rewrite was used.

## Caveats

The optional DABOOK environment was also audited during ingestion work. Its audit found vulnerabilities in Certifi 2026.7.22, OpenTelemetry API 1.45.0, and Pillow 12.3.0. Certifi supports model/download TLS verification; OpenTelemetry handles tracing in the sidecar web stack; Pillow handles rendered images used by OCR/Docling and document fixtures. Compatible declared constraints now require Certifi >=2026.10.18, OpenTelemetry API >=1.45.1, and Pillow >=13,<14 (Docling declares Pillow <14). The installed versions are 2026.10.23, 1.45.2, and 13.0.0. A fresh `uvx pip-audit --path services/dabook/.venv/Lib/site-packages` reports no known vulnerabilities. Extraction regression tests and real scanned-PDF OCR pass after these updates. The Python lockfile includes these floors.

- REA declares Node `^22.23.4 || ^24.22.1 || >=26.12.1`. Although the default host Node is 24.15.0, the follow-up explicitly selected the already-installed Node 24.22.1 runtime and passed eight isolated live API workflows, including actual native decompilation. See the [follow-up evidence](../remaining-work/2026-11-01/follow-up/README.md). User runtime configuration and private job storage were preserved.
- The client native Rolldown package initially materialized a corrupt Windows binary, and a later Radix installation was missing its declared ESM entry point. Each exact package directory was moved to an ignored recoverable backup and reinstalled; direct imports, the full client suite, and the production build then passed. Clean-machine `npm ci` materialization across supported platforms remains separate release lifecycle evidence.
- Deepmerge remains a scanner-visible development-only residual because no patched npm release exists; the locally patched behavior is independently tested. Replace the patch when a reviewed upstream release closes the reproduced behavior.
- npm 11 prints explicit peer-override warnings for the scoped older grammar metadata during clean installs. The compatibility is covered by native regression tests; no global `.npmrc`, `legacy-peer-deps`, or unrelated peer suppression was added.
