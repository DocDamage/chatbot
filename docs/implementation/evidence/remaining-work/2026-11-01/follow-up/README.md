# Docling, development tools, and REA follow-up

Local validation on `codex/coding-alias-context`, November 1, 2026. This supplements the [original checkpoint](../README.md); it does not replace historical results. Changes remain local. Ollama evaluation is deferred at the user's request, and no training job was started.

## Equation and table quality

The original calibration PDF now produces the correct squared energy equation and its complete table. A separate two-page generated fixture produces all three expected equations correctly: a power, a stacked fraction, and the quadratic formula. Both documents preserve their table rows; prose/code controls produce no false positives. See the benchmark JSON, expected regions/patterns, and semantic reports in this directory. The fixture is generated by `scripts/dabook/quality_fixtures.py`; `scripts/dabook/check_quality.py` checks regions, LaTeX structure, negative controls, and table rows. These small generated fixtures are regression evidence, not a population accuracy estimate.

The accepted implementation retains Docling's native parser and renderer, recovers conservative native-glyph formula candidates before enrichment, and refines initially empty formula regions to bounded ink crops. CPU inference uses float32 with 0.08 crop expansion. Crop corrections allow at most 5 PDF points inward and 2 outward on each edge, retaining at least 75% of each dimension. Rotation and text/geometry guards retain upstream behavior when recovery is ambiguous. Docling conversion runs once for the complete book; a replanning regression covers switching from several PDFium shards without duplicate extraction or lost pages.

Rejected experiments are retained in ignored local logs: an alternative layout model lost the calibration table; a full PDFium Docling backend corrected formulas but also lost that table; disabling native rendering prevented enrichment; unrefined native formula crops added a spurious square root to a fraction. None are accepted results. Correcting empty pre-enrichment formula text handling and ink crops passes both documents. In the final two-document process, conversion took 90.078 seconds for the two-page fixture and 25.656 seconds for calibration, including respective model setup/warm reuse. These are host observations, not performance guarantees.

Validation used Python 3.12.12 and the frozen lock with Docling 2.145.0, Transformers 5.22.1, and Torch 2.15.0. A disposable system-drive environment avoided severe import latency observed in the workspace-drive environment. Cached model inference ran offline with two CPU threads. User Python settings and the existing workspace environment were preserved.
